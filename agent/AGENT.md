# CampusAI — University Helpdesk Agent

## What it does

CampusAI is a conversational assistant for university students. Students ask questions in plain language — about their grades, upcoming exams, fee payments, placement drives, scholarship deadlines, or campus facilities — and the agent routes each query to the right data domain and returns a direct, factual answer.

University services are scattered across separate portals and offices. A student trying to check their attendance, understand a fee deadline, and find an upcoming placement drive has to navigate three different systems. CampusAI brings all six domains into a single chat interface.

## Domains covered

| Domain | Examples |
|---|---|
| Academic | Courses, attendance, timetable, CGPA, academic regulations |
| Examinations | Exam schedule, hall tickets, results, internal assessments |
| Finance | Fee structure, payment status, receipts, refund policy |
| Placements | Drive schedules, eligibility, companies, internships |
| Scholarships | Programs, eligibility criteria, application steps, deadlines |
| Campus (General) | Facilities, transport, library, contacts, academic calendar |

## How the decision works

Before the language model runs any tool, Strands Decider 2B reads the student's message and selects which of the six tools should handle it. This is the **#tool-selection** pattern.

The Decider returns a probability distribution over the six tools (plus a `none` option). When one tool scores above 0.65 confidence the agent is built with only that tool — fewer tokens, a faster LLM turn, and no cross-domain hallucination. When confidence falls below 0.65 the agent receives all tools and the LLM decides, or the caller returns a clarifying question.

## Why Strands Decider 2B

- **Speed:** a single forward pass is faster than a full LLM tool-selection call
- **Cost:** a 2B decision model is cheaper per token than a large generative model
- **Calibration:** the Decider returns explicit probabilities, so low-confidence cases can be handled deliberately (ask for clarification rather than guessing)
- **No hallucination on routing:** the Decider classifies intent; it does not generate answer text, so it cannot fabricate domain information

Measured latency and accuracy numbers are generated by `./kit bench` and recorded in `submission/bench/results.json`.

## Reusable pattern

The decision pattern lives in `agent/decision.py`. Replace `TOOLS` with your own `@tool` functions (each with a one-line docstring), adjust `THRESHOLD`, and the Decider will route to your tools. No retraining needed.

## Tech stack

- **Agent runtime:** Strands Agents SDK
- **Decision model:** Strands Decider 2B
- **Generative model:** Amazon Nova Pro (Amazon Bedrock)
- **Data:** synthetic demonstration data in `agent/data/*.json`
- **Kit:** AWS User Group Madurai Strands Decider hackathon kit
